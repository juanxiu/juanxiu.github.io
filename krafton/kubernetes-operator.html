서비스 중단 이후의 수동 점검 문제

서비스 중단이 반복됐지만 애플리케이션 상태와 관련 로그를 수동으로 확인해야 해, 장애 파악과 대응이 늦어졌습니다. 이를 개선하기 위해 Kubernetes Operator를 개발해 배포 상태 점검과 Slack 알림을 자동화했습니다.

CRD와 Reconcile을 활용한 리소스 관리

  • CRD로 배포 설정의 구조 정의
  • Reconcile에서 Custom Resource를 읽어 Deployment 구성
  • 실행 상태와 함께 서비스 준비 상태를 확인해 Slack으로 알림
  • 실제 상태 변화와 알림 수신 내역을 대조해 동작 확인

AI 기반 로그 분석과 장애 대응 자동화 체계

장애 테스트마다 반복되던 로그 조회와 보고 업무를 줄이고자 LLM에 Loki API를 연결했습니다. 단일 애플리케이션의 로그만으로 장애 전파를 추적하기 어려워, 호출 관계와 자원 사용 관계를 온톨로지로 정의하고 그래프DB에 지식 그래프를 구축했습니다. LLM이 이를 참조해 연결된 애플리케이션의 로그와 자원 상태까지 분석하는 자동화 체계를 완성했습니다.

  • 주간 리포트 작성 시간 150분 → 30분으로 80% 단축
  • 기존 데이터셋으로 모의 장애를 재현해 원인 분석 성공률 90% 확인
  • 작업 지침과 조회 도구를 플러그인으로 공유해 팀의 로그 분석 절차 표준화
