고객용 셀프서비스 플랫폼 구축

고객사의 데이터 변경 요청이 잦아 직원이 전처리와 지식베이스 갱신을 반복해야 했습니다. 고객이 직접 최신 데이터를 반영하는 셀프서비스 환경을 제안했습니다.

AS-IS

담당자에게 데이터 갱신 요청

데이터 관리 기능은 사내 VPN이 필요한 직원용 플랫폼에 있었습니다. 고객에게 VPN 계정을 발급하는 방안은 팀 논의 결과 보안상 어려웠습니다.

TO-BE

고객이 직접 데이터 등록·갱신

고객에게 개방할 API를 선별하고, Nginx와 백엔드로 내부 시스템을 연결했습니다. 에이전트 루프를 설계해 고객의 요청에 필요한 작업을 판단하고 기존 ETL 파이프라인을 실행하도록 했습니다.

  • 고객 인증과 권한에 따라 내부 API 접근 제어
  • 데이터 전처리부터 지식베이스의 필요한 부분 갱신까지 자동화

결과고객 사용 교육까지 맡아 고객사의 평균 솔루션 도입 기간을 6주에서 4주로 단축하는 데 기여했습니다. 플랫폼의 기능을 MCP로 전사에 공유해 고객사별 기능 등록 절차를 표준화했습니다.

AI 에이전트 파일 입력 구조 설계

AI 에이전트에 어떤 정보를 언제 전달할지 설계했습니다. 파일 저장과 모델이 본문을 읽는 시점을 분리해 반복 입력을 줄였습니다.

AS-IS

파일 본문 전체를 매번 전달

파일이 필요하지 않은 요청에도 전체 본문이 모델 입력에 포함됐습니다. 같은 내용을 반복 처리하면서 컨텍스트가 커졌습니다.

TO-BE

도구 기반 파일 조회

파일 원문은 S3에 저장하고 파일 ID는 DB에서 관리했습니다. 모델에는 파일명과 ID만 전달하고, Tool Calling으로 필요한 본문을 조회해 결과를 다음 입력에 반영했습니다.

  • 서버의 TTL 캐시로 동일 파일의 조회 결과를 재사용해 S3에 대한 반복 접근 감소

결과파일 전체를 매번 모델에 전달하던 작업을 없애고, 실제로 읽은 범위만 다음 입력에 포함하도록 변경했습니다.
