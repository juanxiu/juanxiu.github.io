고객용 플랫폼 구축

데이터가 바뀔 때마다 고객이 전처리와 지식베이스 갱신을 요청하고 기다려야 했습니다. 고객이 직접 데이터를 관리하는 방안을 후속 과제로 제안하고, 데이터 최신화를 지원할 플랫폼 환경을 구축했습니다.

AS-IS

담당자에게 데이터 갱신 요청

데이터 관리 기능은 사내 VPN이 필요한 직원용 플랫폼에 있었습니다. 고객에게 VPN 계정을 발급하는 방안은 팀 논의 결과 보안상 어려웠습니다.

TO-BE

고객이 직접 데이터 등록·갱신

팀과 개방할 기능을 협의하고 필요한 API를 선별했습니다. Nginx와 백엔드로 내부 API를 연결해 고객용 웹 접속 환경을 구성했습니다.

  • 백엔드에서 고객 인증과 권한 확인
  • 기존 ETL 파이프라인을 통해 지식베이스 최신화

결과플랫폼 사용법 교육까지 지원해 팀의 평균 솔루션 도입 기간을 6주에서 4주로 단축하는 데 기여했습니다.

AI 에이전트 파일 입력 구조 설계

AI 에이전트에 어떤 정보를 언제 전달할지 설계했습니다. 파일 저장과 모델이 본문을 읽는 시점을 분리해 반복 입력을 줄였습니다.

AS-IS

파일 본문 전체를 매번 전달

파일이 필요하지 않은 요청에도 전체 본문이 모델 입력에 포함됐습니다. 같은 내용을 반복 처리하면서 컨텍스트가 커졌습니다.

TO-BE

도구 기반 파일 조회

원문은 S3에 보관하고 모델에는 파일명과 ID만 전달했습니다. 본문이 필요할 때 파일 읽기 도구를 호출하도록 구성했습니다.

  • 서버의 TTL 캐시로 파일 재사용
  • 도구 응답 크기를 서버에서 명시적으로 제한

결과파일 전체를 매번 모델에 전달하던 작업을 없애고, 실제로 읽은 범위만 다음 입력에 포함하도록 변경했습니다.
